# ai-systems-marketplace

Магазин плагинов для **Claude Code**. Раздаёт **споры** — плагины, которые одной командой разворачивают готовую систему управления проектом: память, правила, автоматизацию и «ризоматический паспорт» (родословную системы).

Ниже — как поставить.

## Установка

Спора ставится через **Claude Code** — это «рабочий» режим Claude, в котором он умеет выполнять команды на вашем компьютере. Хорошая новость: открывать терминал и печатать команды вручную не нужно — достаточно попросить Claude словами.

### Способ 1 — через приложение Claude, режим «Код» (проще всего)

Если вы пользуетесь приложением Claude для Mac — действуйте так:

1. Откройте приложение и переключитесь в режим **«Код»** (Code). Если он попросит выбрать папку — выберите ту, где будет жить проект (например, «Документы»).
2. Напишите Claude обычными словами, например:
   > Поставь, пожалуйста, плагин `project-setup` из GitHub-маркетплейса `mrdmitrydouble/ai-systems-marketplace`.
3. Claude начнёт установку и будет показывать кнопку **«Разрешить»** (Approve) — нажимайте её. Печатать команды самому не нужно.
4. Когда Claude скажет, что плагин установлен, — перезапустите приложение (или попросите: «перезагрузи плагины»).
5. Запустите разворачивание системы — откройте сессию Claude Code в новой папке, в которой хотите развернуть систему, и напишите:
   > /project-setup:project-setup

   Или просто словами: «Инициализируй проект, я получил спору».

Готово — Claude создаст структуру памяти, правила работы и автоматику нового проекта.

⚠️ Это работает именно в режиме **«Код»**, потому что там Claude может выполнять команды. В режиме «Чат» установка плагинов недоступна.

### Способ 2 — командами (если вы уже работаете в Claude Code)

Введите эти две строки по очереди и нажмите Enter после каждой:

```
/plugin marketplace add mrdmitrydouble/ai-systems-marketplace
/plugin install project-setup@ai-systems-marketplace
```

Затем введите `/reload-plugins` (или перезапустите Claude Code) и запустите инициализацию словами: «Инициализируй проект, я получил спору».

Если Claude отвечает, что команда `/plugin` ему не знакома, обновите Claude Code до последней версии.

### Что нового в 8.1.2

Про то, что раздражало больше всего: «прошлая сессия не закрыта», «слияние позже» и вопросы
«это реальная сессия или забытое окно?».

- **Страж параллельных сессий снова работает.** Десктоп Claude сменил путь к процессу claude, и
  модуль живости перестал находить сессии вообще — защита была молча выключена. Теперь claude
  узнаётся во всех видах установки (десктоп, CLI, npm), а `quick_health` сразу скажет, если
  страж снова ослепнет.
- **Мешает только тот, кто работает.** Десктоп держит открытые окна живыми сутками. Теперь
  соперник — только сессия, которая работала последние 10 минут (считая её субагентов). Открытое,
  но забытое окно не уводит записи в инбокс и не вызывает вопросов при `/end`. От затирания файлов
  страхует сам Claude Code: правку файла, изменённого после чтения, он отклоняет.
- **«Не закрыта» — только за свою работу.** На старте сессия запоминает, что уже лежало
  незакоммиченным, а в конце сравнивает. Черновик, который неделями лежит в папке, больше не делает
  каждую сессию «незакрытой», а настоящая работа видна, даже если у файла старая дата (перенос,
  копия, распаковка, `git mv`). Устаревший маркер при чистом дереве снимается молча, а маркер, в
  снапшоте которого может лежать отброшенная правка, остаётся.
- **Smoke-тест: 37 проверок.**

Обновить уже развёрнутую систему: раздел «harness v5.1 → v5.2» в `MIGRATION.md` (пять файлов и
три точечные правки), после — закрыть и заново открыть окна, открытые в этой папке. Попроси агента:
«обнови harness до v5.2 по MIGRATION.md».

### Что нового в 8.1.1

Патч: всё, что мешало с первого дня работы.

- **Ложное «прошлая сессия не закрыта».** После первой записи в память Python оставлял служебную
  папку `__pycache__`. Git считал её незакоммиченной работой, и после каждого фонового прогона
  (дайджест, хартбит) следующая сессия начиналась в режиме восстановления. Тот же эффект давали
  служебные файлы самого harness: маркер соседней открытой сессии, отметки прогонов и старый
  маркер, который переписывал сам себя. Теперь страж не оставляет кэш, а снапшот не считает всё
  это работой.
- **Smoke-тест строже: 24 проверки вместо 17.** Шесть новых ловят ложный «RECOVERY», ещё одна —
  отсутствие `session_liveness.py` в самом проекте: раньше тест оставался зелёным и без него.
  Глобальная подпись коммитов (`commit.gpgsign`) больше не роняет тест.
- **Установка без обхода всего диска.** Раньше спора искала свою папку через `find ~`. На Mac
  это минуты ожидания, системные запросы доступа к Фото и Документам, а после обновления — риск
  взять старую версию. Теперь путь подставляет сам Claude Code.
- **Верная команда запуска** в этом README: `/project-setup:project-setup`. У плагинов команда
  составная: имя плагина и имя скилла.

Если система уже развёрнута на 8.1.0: `/plugin update` не трогает хуки, скопированные в проект.
Попроси агента: «обнови harness до v5.1 по MIGRATION.md» (три файла, чистка `__pycache__` и
`.gitignore`). На 8.0.x и раньше трёх файлов мало — попроси переустановить harness целиком по
`harness/README.md`.

### Что нового в 8.1.0

Версия про одно: **система может выглядеть здоровой и при этом не работать.** Все правки
ловят именно это.

- **Фикс, важный для уже развернувших.** В инструкции установки отсутствовал
  `session_liveness.py`. Без него `memory_write_guard.sh` пропускает запись **молча**
  (fail-open): хуки на месте, `ls .claude/hooks/` показывает четыре файла — а защиты от
  параллельных сессий нет вовсе. Если разворачивал систему по инструкции v8.0.x, скопируй
  файл в `System/scripts/` и прогони `smoke_hooks.sh`.
- **Приёмка установки — прогоном, а не списком файлов.** `smoke_hooks.sh` гоняет настоящие
  хуки на подготовленном вводе в изолированной песочнице, 17 проверок. Красный smoke =
  harness не установлен, сколько бы файлов ни лежало в папках.
- **Дрифт уставки.** `quick_health` проверяет, что `CONSCIOUSNESS.md` лежит в корне (в
  Черновиках он не грузится в контекст и уставка мертва) и что его хеш сходится с
  `genome_hash` в паспорте — молчаливая правка генома становится видимой.
- **«Прогон без следа».** `check_pulse_freshness.sh` смотрит не на самоотчёт периодической
  задачи, а на реальный коммит-доставку. Реестр не настроен → говорит «не проверено», а не
  «всё свежо»: зелёный отчёт при нулевой проверке — ровно та ошибка, которую детектор ловит.
- **Frozen-зоны по факту.** `frozen_check.sh` ловит правку в обход стража — через Bash или
  руками, — сверяясь с git, а не с намерением.
- **Четыре подагента** (аудитор, поисковик, документалист, мигратор) с полями `name` и
  `description` в заголовке. Без них Claude Code подагента не видит вообще, а инструкции
  проекта продолжают на него ссылаться.

Ломающих изменений нет: пути и имена не менялись, обновление аддитивное.

## Обновление (доставка новой версии)

Когда выходит новая версия споры — обновить уже установленный плагин:

```
/plugin marketplace update ai-systems-marketplace
/plugin update project-setup@ai-systems-marketplace
```

### ⚠️ Переход на v8 (breaking change)

В версии 8.0.0 имена папок и файлов структуры стали **латинскими** (`Project/`, `System/memory/`, `Documents/Drafts/` вместо `Проект/`, `Система/память/`, `Документы/Черновики/`) — среда отвергала не-ASCII имена в спорах.

- **Новые проекты** разворачиваются сразу на латинской структуре — делать ничего не нужно.
- **Проекты, развёрнутые на старых (кириллических) версиях,** продолжают работать со своей структурой: обновление плагина не переименовывает уже созданные папки. Чтобы перейти на латиницу — попросите агента провести миграцию по `MIGRATION.md` (отдельная операция с бэкапом).

## Для мейнтейнера (Дмитрий)

**Источник истины** скилла — мета-проект: `Создание ИИ систем/Проект/Документы/Скиллы/project-setup/`. Этот marketplace — артефакт сборки (как раньше ZIP).

**Цикл выпуска новой версии:**
1. Отредактировать скилл в мета-проекте, прогнать ревью (адверсариальное) + smoke-тесты harness.
2. Синхронизировать в плагин: `cp -R "…/project-setup/." plugins/project-setup/skills/project-setup/`
3. Поднять `version` в `plugins/project-setup/.claude-plugin/plugin.json` И в `.claude-plugin/marketplace.json` (держать синхронно — при расхождении plugin.json выигрывает молча).
4. **Обновить ОТОБРАЖАЕМУЮ версию во ВСЕХ местах, где она продублирована** (класс рассинхрона, найден в сессии 55): таблица в этом README + заголовки `(vN)` в `SKILL.md`/`MIGRATION.md`/`INSTRUCTION.md`/`STRUCTURES.md` + `skill_version` в шаблоне VERSION.md (внутри STRUCTURES.md). Не глазами — линтом (п.5).
5. **Линты приёмки (оба → `exit 0`):**
   - `bash scripts/check-version-sync.sh` — major из plugin.json == заголовки скилла + шаблон. Ловит «обновили манифест, забыли заголовки» (так и было: манифест v8, заголовки v7 — в «Отобразить скилл» торчала старая версия).
   - `bash scripts/check-spore-ascii.sh` — не-ASCII имя файла/папки в `plugins/` → загрузчик отвергает плагин. Содержимое кириллицей — можно; имена — только ASCII.
6. `git commit + push`. Узлы получают обновление через `/plugin update`.

**Доступ:** репозиторий публичный — любой может подключить marketplace и поставить спору. Приватных данных в спорах нет (это шаблоны системы).
